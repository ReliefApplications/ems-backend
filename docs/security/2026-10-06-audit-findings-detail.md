# HEMS security audit — Phase 1 finding detail

Date: 2026-10-06
Scope: hems-back (this repository, branch `next`, 2.18.0-rc.12), hems-front, hems-infra, and the deployment configuration of hems-email-function and hems-pull-function.
Status: Phase 1 (audit only). No code was changed. This file is the working detail behind the findings table; the client-facing report will be written in Phase 3 as `docs/security/<date>-security-audit.md`.

Method: the code base was mapped (stack, entry points, auth model, data stores, external services, deployment), then eight areas were reviewed in parallel: authentication and sessions, GraphQL authorization, REST routes, GraphQL input handling, secrets (working tree and git history), dependencies, front-end, infrastructure and CI, and data exposure. Every Critical was re-verified in source by the lead reviewer; one bypass (C-02) was reproduced locally.

Rules applied: no production system was touched; no secret value is recorded here (secrets are referenced by file, line and type only); findings not confirmed end to end are marked "unverified".

Severity: Critical = exploitable now by a low-privileged or external actor with high impact. High = exploitable now with significant impact or requiring a modest privilege. Medium = exploitable with conditions, or a hardening gap with real impact. Low = minor or latent.

Column "Safe now" states whether the fix can be shipped without a product decision or a prior check on production data or the front-end.

Sources: 9 area reports + lead verification. "Conf." = confirmed by reading full code path (lead re-verified all Criticals in source). Paths relative to hems-back unless prefixed front:/infra:/func:.
